Verify · in-browser checker

Verify

Paste an emem token, a note name, a receipt or a log hash. The page fetches the bytes and proofs from emem.dev, then checks the hashes and signatures in this tab against the published key.

key from
/.well-known/emem.json
code
/emem-verify-core.js (BLAKE3, Ed25519)
API equivalent
POST /v1/verify_receipt

Check a token

reads the kind from what you paste

Examples, each minted live when you click:

    What each result means

    ✓ verified
    A signature was checked in this tab against the key it names.
    ○ resolved
    The bytes were found and hash to their name. No signature covers them.
    ✗ failed
    A check did not pass. The failing step says which and why.

    Each step is marked ✓ passed, ✗ failed, or · for information. If the in-tab verifier fails its self-test, the page checks nothing and says so.

    What you can paste

    emem:fact:one signed reading; the legacy memt: form too
    emem:bundle:a set of facts
    emem:cell:a place, about 10 m on a side
    emem:entity:an object's identity
    emem:raster: emem:cube: emem:rasterset:a signed field, a field over time, several fields
    emem:tree:one root over a note's units
    emem:trace:an attested run on a device
    emem:state:one stage of an answer's reasoning
    26 charactersa signed note, by name
    52 charactersa fact_cid or other content name
    {"receipt":…}a receipt JSON
    /v1/log/sththe signed log head
    entry_hash=…one log entry
    r1 …an r1 line, by its ref

    What rests on whom

    emem.dev supplies bytes and proofs. This tab decides whether they hold. A check that relies on the responder's word is labelled as such in its step.

    To check without this page, see How it works: hash and sign or the wire format.
