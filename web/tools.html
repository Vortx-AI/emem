emem_find_similark-NN over the corpus by embeddingCall this for 'find places like X' or 'where else looks like this', or with an embedding.

Find the k nearest cells in the corpus by cell embedding or by an inline vector. The answer has `neighbors`, nearest first, each with `cell`, `score`, `lat`/`lng` and `band_used`, and a signed receipt over the vectors it read. `mode` sets the scoring. cosine is exact fp32. hamming counts sign bits and scans many more cells for the same budget. hamming_then_rerank does both. `k` is 1 to 1000, default 10. emem_band_compositeBand composite: a signed cloud-masked median over a windowCall when a world model or an analyst needs the clean composite texture over an area across a season.

Mint a signed, cloud-masked median composite over a date window as a raster-shaped field. This is the clean, gap-filled texture a world model actually drapes, rather than one cloudy scene. It reads every Sentinel-2 scene in [start_date, end_date] over the bbox. It masks each scene per pixel by its SCL scene-classification class. The default rejects {0,1,3,8,9,10}: no-data, saturated, cloud shadow, cloud, cirrus. It KEEPS snow 11 because snow is surface, not occlusion. A snow-rejected median would fabricate a bare winter scene. Override the default with mask_policy. It takes the per-pixel lower-of-two median, and never averages two measurements into a value nobody took. A pinned min_valid_count applies: below it, a pixel is nodata. The signed derivation pins the mask policy, min_valid_count, and the exact member scene list. Thus a stranger re-derives the composite pixel for pixel from the same scenes. emem_reasonCompose a prose answer over signed facts (LLM, labelled)Reach for this only when the question needs prose composition across several facts and the caller explicitly wants a model in the loop.

The opt-in reasoning tier. It grounds your question through emem_ask (deterministic, signed). Then the responder's local model composes a prose answer over that envelope. The prose is model_output and signed:false by construction, and it is never evidence. The grounding block beside it (fact_cids + receipt) is the evidence. The model runs greedily (temperature 0) under a per-model single-flight lock. Thus a cold load never fans out. Also, a slow deliberation on one model cannot head-of-line-block a fast answer on another. Pass `model` to choose which one composes. Call with no arguments to see which are routable. For anything a signed envelope already answers, use emem_ask instead and skip the model entirely.
