The read surface.

Every read is the same handler whether you reach it over MCP or REST. This page is the human-readable index of that surface: client setup, the high-traffic endpoints, the one-shot domain tools, the twelve hunter events, and the physics solvers. The full machine contract is /openapi.json.

Reads are idempotent. The MCP layer is a convenience wrapper over the same handlers behind /openapi.json. Writes (/v1/attest, /v1/challenge) require an Ed25519 secret the attester controls and are not exposed via MCP for that reason. The recommended first tool is emem_ask: it routes a free-text question through place resolution, recall, and the applicable algorithms in one call.

03Primitives

The read surface composes from a small set of primitives. Each returns a signed receipt over a content-addressed fact, so any answer is reproducible on another peer.

PrimitiveWhat it does
recallread facts at a cell for one or more bands; materialises on miss and signs the result
askintent-routed Q&A: place resolution → recall → applicable algorithms, one call
find_similark-NN over foundation embeddings; cosine, hamming, or hamming-then-rerank
trajectoryone band at one cell across a time window → ordered series
compare / compare_bandstwo cells, or two bands at one cell, side by side with a signed delta
diffsigned delta of one band between two tslots; rejects a == b
query_regionaggregate one band across a region's sampled cells
field_boundariesagricultural field polygons from Fields of The World, overlaid on recall
verify / verify_receiptrecompute the preimage and check the Ed25519 signature over BLAKE3

Empty is a signed answer, not a 404: when a cell has no fact for a band, the responder returns a signed record of that absence rather than failing silently.

04Hunter: open-world discovery

/v1/hunt takes an event keyword plus a region, geocodes the region, fans out across up to 32 sampled cells, recalls each event's primary input band, and returns the top 8 hotspots ranked by that scalar — each with its cell64, lat/lng, recalled value, a fact_cid, and a scene.png URL.

Twelve events ship today. The registry decides which algorithm runs.

algal_bloomchlorophyll proxy from NDCI with an NDWI water gate — algal_bloom_chlorophyll_ndci@1
deforestationNDVI-drop alert against the recent baseline — deforestation_alert_ndvi_drop@1
flood_extentSentinel-1 SAR VV threshold under cloud — flood_extent_sar_threshold@1
wildfiredNBR burn intensity, fine-tuned — wildfire_burn_intensity_dnbr_finetune@1
urban_heat_islandMODIS LST against canopy cover — urban_heat_island_lst_canopy@1
methane_plumeSWIR anomaly over baseline — methane_plume_swir_anomaly@1
landslidepost-event Sentinel-1 ΔVV with slope — landslide_post_event_sar_dnn@1
droughtSPI meteorological drought index — spi_meteorological_drought@1
soil_salinitysoil salinity index from optical bands — soil_salinity_index@1
crop_stresscrop stress score from NDVI / NDRE — crop_stress_score@1
water_turbiditySentinel-2 red-band reflectance, water-mask gated — water_turbidity_red_band@1
oil_slickno algorithm in the registry yet: returns status not_yet_implemented with pointers at SAR-darkening + turbidity proxies

For free-text discovery (“find oil spills in the Persian Gulf”, “where is deforestation happening in the Amazon”), the classifier in /v1/ask routes the same hunter path. The ranking uses the algorithm's primary scalar input only; for the full per-cell score, fetch the formula at /v1/algorithms/<key> and apply it client-side over the same recalled bands.

05Physics & forecasting

Four solvers run on the same signed grid. Each returns the field plus the source fact_cids its initial condition was built from, so the inputs are as verifiable as the output.

MethodPathMCP toolModel
POST/v1/heat_solveemem_heat_solve2-D explicit FTCS heat diffusion on a MODIS land-surface-temperature stencil (CFL-stable)
POST/v1/wave_solveemem_wave_solve1-D shallow-water equation along a seaward bathymetry gradient
POST/v1/jepa_predictemem_jepa_predictclosed-form NDVI AR(2) seasonal model with fixed coefficients
POST/v1/jepa_predict_v2emem_jepa_predict_v2Tessera-embedding dynamics; short-circuits to an identity baseline (untrained_baseline)

/v1/heat_solve integrates 2-D explicit FTCS heat diffusion on a MODIS land-surface-temperature stencil, kept CFL-stable (for example, urban-heat spread). /v1/wave_solve integrates a 1-D shallow-water equation along a seaward bathymetry gradient (for example, coastal swell), and rejects a land-locked profile rather than returning a meaningless field.

/v1/jepa_predict projects an NDVI trajectory forward with a closed-form AR(2) seasonal model and fixed coefficients: deterministic and reproducible. /v1/jepa_predict_v2 runs Tessera-embedding dynamics; when it cannot improve on the last observed vintage it short-circuits to that identity baseline and the receipt carries untrained_baseline. The v2 forecast is an untrained baseline, never a learned prediction.

06The full machine contract

This page lists the surface agents reach for most. The complete, authoritative contract is /openapi.json — 95 paths, 92 of them under /v1/*.

Browse it interactively at the API reference (ReDoc). The 159 algorithm recipes are listed at /v1/algorithms (each carries a formula, input bands, a citation, an accuracy band, and a learned_from provenance line); the 27 topics at /v1/topics; the 122 materializer-wired band names across 42 cube slots and the 46 source schemes are introspectable through the registries. Discovery for agents starts at /v1/agent_card, /agent.json, or /.well-known/mcp.json.
