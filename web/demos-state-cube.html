One endpoint, two views. POST /v1/state with view=encoder returns one named foundation embedding at its native dimension (Tessera 128-D, Clay 1024-D, Prithvi 1024-D, Galileo 768-D). view=cube returns the responder's full 1792-D voxel, the fused fingerprint that lays those four foundation encoders plus the raw sensor and derived bands into canonical offset order, with per-band coverage[] so an agent can tell attested-zero from not-yet-materialised, and extras that preserve full Clay/Prithvi 1024-D fidelity when the cube slot truncates them. The cube is a fixed-width fingerprint; the extras carry the full payload. Pick a place, hit run, watch a real responder fill the slots in front of you.

step 2

state · view=encoder

POST /v1/state

Single-encoder state vector at the cell. Returns the encoder's native vector, an L2 norm, a fact CID, and a pre-composed memory token memt:<cell>:<fact_cid> for citation.

step 3

state · view=cube

POST /v1/state

Full 1792-D voxel across every wired band, in canonical offset order. With materialize=true cold bands trigger upstream fetches. The response carries coverage[] (per-band status), state_cid (BLAKE3 over canonical LE f32 bytes), and extras[] for any encoder whose native dim exceeds its cube slot.

step 4

state_multi · cross-encoder fan-out

POST /v1/state_multi

Three foundation encoders at the same place, side by side. Useful for cross-encoder consensus (do Tessera, Clay, and Prithvi agree on the archetype here?) and redundancy-aware reasoning.
