How emem works

Every place on Earth resolves to a stable token. Every observation at that token becomes a signed, content-addressed record, tagged with how it was produced, so an agent can tell a raw sensor reading from a model’s estimate. Records link through typed edges and improve through contradiction scoring and a refinement loop, over a typed, bi-temporal memory substrate.

01Tokenising Earth: cell64

A language model tokenises text so its layers can reason over symbols instead of raw characters. emem tokenises Earth for the same reason: agents need a finite alphabet for places before they can reason, remember, or cite.

The cell64 grid is that alphabet: a 64-bit identifier per ~9.55 m square at the equator, content-addressed, deterministic, and the same on every responder. Antimeridian and pole canonicalisation are pinned in code, so two queries 1 m apart land in the same cell, every time. An LLM asked what is at a place will usually guess; cell64 is the missing handle it can anchor on instead.

Nothing else in the protocol is Earth-specific. The signed fact, the receipt preimage, the provenance class, and the token grammar operate on any canonical address; cell64 is the first addressing scheme and satellite observation the first substrate. A sensing domain with its own canonical address space can join the same attest, recall, cite, and verify path unchanged.

The right-hand column is what makes the answer durable. A receipt-bearing fact survives the session, survives the model, survives the responder. Quote the fact_cid in a chat and your colleague can pull byte-identical bytes from any replica and verify the signature in their browser at /verify, with no callback to the issuer. The recall surface is keyed on three coordinates: Cell × Band × Tslot → Fact, where Band names a measurement (elevation, NDVI, land cover, a foundation embedding) and Tslot names a Unix-epoch time window.

02Signing, CID, and the receipt preimage

The responder pubkey is the only trust anchor. The preimage is a deterministic byte string any agent can recompute offline to check the signature. A receipt issued today verifies in any year, on any node, as long as the pubkey is preserved.

Each fact body is encoded as canonical CBOR and hashed with BLAKE3; the content id (fact_cid) is that digest, base32-nopad, all 32 bytes of it: 52 characters that name the exact bytes. The CID is the citation: re-encode the body and the CID drifts, so a quoted CID pins exact bytes. A fact, throughout, is a signed observation, wire-named: the signature proves attestation and integrity, never objective truth. The body carries confidence and uncertainty, and the band’s provenance class (section 03) says how the value was produced. The receipt signs over a preimage that names the request, the time served, the primitive, and every cell and CID in the answer.

The receipt’s preimage_version field selects the rule. Version 1 domain-separates and length-prefixes every field, computing blake3("emem.preimage.v1" ‖ "receipt" ‖ tagged(request_id, served_at, scope?, as_of?, edges?, manifest?, primitive, cells[], fact_cids[])), where the optional tagged segments appear only when the receipt body carries the matching field, so no two distinct responses can ever share signed bytes, and the merkle tree uses RFC 6962 leaf/node separation. The original concatenation rule shown below still verifies pre-v1 receipts unchanged.

PSEUDOpreimage (pre-v1 rule)
blake3(
    request_id || "|" || served_at  || "|" || primitive || "|" ||
    cell1 "," cell2 "," ... || "|" || cid1 "," cid2 "," ...
)

# trailing commas after the last cell and last cid are intentional
# the signing loop appends "," after every entry
PYTHONverify_offline.py
import blake3
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey

r = receipt  # the receipt block from any /v1/* response

h = blake3.blake3()
for field in (r["request_id"], r["served_at"], r["primitive"]):
    h.update(field.encode()); h.update(b"|")
for c in r["cells"]:     h.update(c.encode()); h.update(b",")
h.update(b"|")
for c in r["fact_cids"]: h.update(c.encode()); h.update(b",")

pk = Ed25519PublicKey.from_public_bytes(bytes(r["responder_pubkey"]))
pk.verify(bytes(r["signature"]), h.digest())
# VALID. no callback to emem.dev required.

03Provenance: could a human or a model have touched the value

A signature proves who signed and that the bytes never changed. It does not, on its own, say whether a person could have edited the number before it was signed. So emem tags every band with how its value is produced, and an agent can tell a raw sensor reading from a model’s estimate before it decides how far to trust either.

The tag is one of five classes. A direct_sensor value is the instrument product itself, with no algorithm in the path. A deterministic_index value is a fixed formula over raw pixels, cell coordinates, or a time series, so anyone holding the cited source recomputes the identical number with no learned weights and no human edit. A model_output value came from a trained model or a published statistical product, so trust rests on a signed model checkpoint rather than on recomputation. A human_curated value traces back to geometry a person drew or placed. A band that has not been tagged yet is unclassified: treated as the lowest trust, and it never claims to be reproducible.

direct_sensorinstrument reading, no algorithm in the path (Copernicus DEM, Sentinel-2 L2A, Sentinel-1 RTC, VIIRS nightlights)recomputable_from_source
deterministic_indexfixed formula over raw pixels, coordinates, or time (NDVI, Horn slope, Fourier position encodings, JRC water rules)recomputable_from_source
model_outputtrained model or published ML product (Tessera, Clay, Prithvi, Galileo, ESA WorldCover, SoilGrids, WorldPop, Hansen)signed_model_checkpoint
human_curateda person drew or placed the geometry (OpenStreetMap, Overture, WDPA, GADM admin, WWF ecoregions)attester_only
unclassifiednot yet tagged; fail-safe lowest trust, never claims tamper-evidenceattester_only

The split that matters is recomputable_from_source: a direct sensor read or a deterministic index that any third party reproduces from the cited raw data, with no model and no human in the loop. Across the 43 bands in the ontology today, 14 are recomputable this way (6 direct sensor, 8 deterministic index), 22 are model output, 5 are human curated, and 2 are still unclassified. These counts are read live from /v1/bands, the same manifest the bands_cid in every receipt pins. An agent that only wants values it can check for itself reads the first two classes and treats the rest as claims it has to trust a signer for. The warning travels in-band: every model_output, human_curated, and unclassified provenance block carries a caution field naming its failure mode (training bias and domain shift, editorial choices and coverage gaps, undeclared method), so the caveat arrives in the same payload as the number instead of living in documentation an agent never read. Recall accepts deterministic: true to keep only the recomputable classes; the filter runs before the receipt is signed.

None of this is a new signed field on the fact, so no fact_cid changed when the tag arrived. The class is declared per band in the content-addressed bands manifest, and that manifest’s id (bands_cid) is already folded into every receipt preimage from section 02. The provenance tag therefore rides into the same ed25519 signature you already verify, and a verifier reproduces the classification offline from the pinned manifest. The signature that proves the number was not altered now also carries how the number was made.

04Connect & evolve: typed edges, contradiction scoring, the refinement loop

emem stores facts and links them. When two sources disagree, it records the disagreement instead of silently picking one. A later attestation supersedes an earlier one on the transaction-time axis without erasing it; the old bytes stay replayable. Contradictions become signed, queryable evidence; nothing is overwritten in the dark.

connect & evolvefacts → typed connections → recorded disagreement → refinement
connect/v1/memory_bundle groups N signed facts into one emem:bundle:<cid> envelope an agent cites as a unit.
disagree/v1/memory_contradictions scores per-band spread and keeps every conflicting fact_cid, with no last-writer-wins.
edgesTyped connections are first-class: (subj, pred, obj, valid_from) with predicates disagrees_with, supersedes, relates_to, queried by /v1/edges/recall and attached to any read with include:["edges"]. The opt-in refinement loop records disagrees_with edges from contradictions automatically.
evolveA new attestation supersedes on as_of_signed_at; /v1/reviews records the task outcome. The earlier bytes never vanish.

Agreement, defined. Two mechanisms, both published, no learned fusion and no hidden calibration. Contradiction scoring, per band at one cell: encoder-independent attestations → normalised disagreement (scalars: spread over the band’s documented physical range; vectors: 1 − mean cosine; categoricals: 1 − mode share) → a scored, addressable contradiction that keeps every conflicting fact_cid. Cross-encoder change ensemble: encoder outputs → per-encoder change index (1 − cosine between that encoder’s two latest vintages, clamped to [0,1]) → each index voted against the registry gate (default 0.15) → change is claimed only when every leg clears → anything less is a signed inconclusive with a typed reason. Formulas and citations: /v1/algorithms.

The loop is honest by construction. A scalar disagreement is scored by normalised spread against the band’s documented physical range; a vector disagreement by 1 − mean cosine; a categorical one by 1 − mode-share. The contradiction is itself addressable, so two agents settle a number by reading the same scored evidence rather than trusting either one. The three edge predicates carry distinct meaning: disagrees_with links conflicting attestations, supersedes marks a transaction-time replacement, and relates_to records a non-conflicting association.

05The memory substrate

Below the recall surface sits a typed, signed, searchable memory substrate. State is the read motion (a per-place dense vector). The memory token is the cite motion (one string any pipeline can paste). Memory files give an agent a writable scratchpad whose every edit is ed25519-signed and content-addressed. Every read carries the same bi-temporal axis pair: as_of_tslot for what the world looked like on a given date; as_of_signed_at for what the system knew on a given date.

Memory here is operational, not metaphor. Write means attest: sign an observation and give it a content address. Read means recall: bi-temporal, receipt-signed. Remember means resolve: a token returns the byte-identical signed bytes it named, in any later session, on any conformant responder. Nothing is forgotten silently: a newer attestation supersedes on the transaction-time axis and the old bytes stay replayable. Anything that cannot be re-verified offline is not in the memory. The formal version, the observation tuple, the property table with mechanisms, and the memory algebra as shipped, is written down at the memory model.

read · 128-D /v1/state {cell, encoder?, view?} Dense signed state at any place. view=encoder returns one foundation embedding (default geotessera, 128-D); view=cube returns the full cube. Cell may be a place name; the geocoder cascade resolves it. Cold cells materialise on miss, then sign.
cite · 1 string /v1/memory_token emem:fact:<cell64>:<fact_cid> Compose a single colon-separated handle the agent can paste in chat, write to a long-term store, or quote across processes. Resolves back to the exact bytes on any responder that holds the fact.
dereference /v1/memory_token/resolve {token} Single round-trip dereference: parse the token, fetch the fact by CID, return the canonical body plus the offline-verify URL. Returns 404 with a typed reason if the responder doesn’t hold the fact.

Two more verbs fan the state read. /v1/state_multi fans across the wired foundation encoders for the same cell, returning a per-encoder map plus a typed missing[] list when an encoder is not wired at this responder. /v1/state_diff takes one cell and two tslots and returns the delta vector, its L2 norm, and the cosine between the two source vectors, with both source fact_cids so the agent can quote both attestations as evidence.

emem wires four foundation encoders: Clay v1.5, Prithvi-EO-2.0-300M-TL, Tessera (the default geotessera 128-D embedding), and Galileo. Galileo is multimodal by design; on this responder only its Sentinel-2 modality is connected today, so the other modalities of the scaffold are present but not yet fed. The encoder map is honest about that: an unwired modality or encoder appears in missing[] rather than being zero-filled.

Above the read surface sits a writable memory substrate the agent owns. /v1/memory_bundle takes N (cell, band, tslot) triples and returns one signed envelope; the emem:bundle:<bundle_cid> token is the multi-fact analogue of emem:fact:. The six file-op verbs (memory_view · memory_create · memory_str_replace · memory_insert · memory_delete · memory_rename) conform to Anthropic’s memory tool spec (header context-management-2025-06-27): the “files” are signed, content-addressed blobs under a path tree rooted at /memories/. Each file carries a kind from the CoALA / LangMem taxonomy (episodic for observations of events, semantic for durable learned facts, procedural for playbooks, resource for scratchpads), and memory_list_by_kind returns only the slice the agent asked for.

Writes can be capability-bound. Paths under /memories/by_attester/<pubkey_short>/… are write-restricted to the holder of the corresponding ed25519 private key: every memory_create in that namespace carries an attester: {pubkey_b32, sig_b32} block where the signature is computed over blake3("emem.memory_write|" + verb + "|" + path + "|" + body_hash). Wrong key → 401 memory_attestation_invalid. Wrong namespace → 403 memory_namespace_violation. The body being hashed is the content the verb produces: the file text for create, the whole file after the edit for str_replace and insert, the empty string for delete. A rename signs over the destination path with the source path as its body, so one signature binds both ends of the move.

Bare /memories/… is not anyone-writable. A responder refuses unattested writes by default with 401 memory_attestation_required, and emem.dev runs that way, so signing is the normal path. An operator who wants the unsigned memory-tool contract back sets EMEM_MEMORY_OPEN=1, or takes the middle setting EMEM_MEMORY_HARDEN_DESTRUCTIVE=1, which accepts unattested writes and edits but makes delete and rename prove a key. No setting opens by_attester.

Three primitives turn the substrate from storage into a queryable knowledge surface. /v1/memory/search embeds the query through BGE-base-en-v1.5 (768-D) and runs cosine against a LanceDB IVF_PQ partition (memory_text_index_d768.lance) over every memory file’s contents, so the agent paraphrases and the index finds. /v1/memory_contradictions walks the parallel multi-attester index and scores disagreement per band kind. /v1/memory/sse opens an event stream filtered by path_prefix · kind · attester so a compliance subscriber or a downstream agent receives every write the moment its sled commit lands.

The substrate is intentionally typed at every boundary. Vector-only bands accept /v1/state; scalar bands return a typed 422 pointing the agent at /v1/recall. Empty cells return a typed 404 pointing at /v1/materializers. Bi-temporal queries with an inverted bound return 400 invalid_temporal_bound; a malformed timestamp returns 400 invalid_signed_at_format. Memory file writes are append-only at the content-address layer: memory_delete drops the path index, but the blob lives on, addressable through memory_file_history. No silent zero-fills, no last-writer-wins, no opaque mutation.

06Absence is a signed answer, not a 404

When a band has no data at a cell, the responder does not return an empty array. It signs an Absence fact with a typed reason. An agent that cites evidence: ["absence_cid_…"] is making a verifiable claim that no data exists, rather than guessing from an HTTP code.

This is what keeps an empty result honest: a signed Absence distinguishes a wrong query (you asked the wrong band) from an empty place (the band is genuinely unattested here). The reason code says which.

◆What reaches emem is a latent, not an image

The bottleneck in Earth observation was never the lens; it is the link. A sensor sees far more than physics will let it send home. For the encoder pipelines, emem stores and exchanges model-derived latent representations rather than raw imagery; scalar bands arrive as plain values. Satellite Earth observation is the first substrate; the roadmap adds fixed sensors, drones, robot fleets, machines, and government registries, with location as the first key throughout.

So the encoder runs at the source: on an orbital payload, a drone, a vehicle camera, a fixed CCTV. A scene becomes a compact latent vector before it ever touches a ground station, orders of magnitude smaller than the raw imagery. emem is the open decoder for that latent. It resolves each one onto the cell64 lattice (section 01) and turns it into a signed fact (section 02). Today those latents come from four open Earth-observation foundation encoders (Tessera, Clay v1.5, Prithvi-EO-2.0, and Galileo), read side by side and scored for agreement (section 04 onward).

The encoder-physically-in-orbit thesis (downlink only the embedding, decode it on the ground) is Vortx's. emem is the part you can read, cite, and self-host: the open decoder and the signed memory. If the encoder kernels are deterministic, a latent emulated on the ground today is the same vector the payload would emit in orbit, so the decoder you run now is the one that flies.

◆The representation is the interface

emem signs the representation agents actually read: the encoder runs where the data is born, and emem stores, indexes, and signs the embedding it emits, not the pixels. An embedding is a representation, not a memory. It becomes part of the memory only once it is signed, content-addressed, and recallable as a record with provenance attached. The protocol does not depend on any one model’s architecture; for the industry direction, Google DeepMind’s Gemma 4 12B announcement (3 June 2026, linked below) describes a model that reads embeddings directly, and that claim stays theirs.

Freezing the encoder buys one more thing: when the readout at a place changes between two visits, the model term of that change is pinned. An embedding record names its encoder checkpoint, so upgrading the model can never masquerade as change on the ground; it shows up as a new, separately signed record instead. Splitting the rest of a change, the world against the instrument against the pixels against the noise, is the change-attribution work on the roadmap, not a shipped capability.

Reference: Introducing Gemma 4 12B, Google DeepMind, 2026.
