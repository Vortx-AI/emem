How emem works

Name a place. Fetch what was observed there. Sign it, log it, cite it. Anyone checks it offline, with no account and no trust in us. A file gets the same treatment: read as its parts, under one signed root.

01Name the place: one address

Two agents describing one place drift apart. Two agents holding one address do not.

  • Quantise. A latitude and longitude become a cell64: a fixed square, the same string on every responder.
  • Resolve a name. Locate tries gazetteers first, then open geocoders. For a bare name it asks Wikidata which place people mean, by how many Wikipedias describe it and whether the name matches exactly.
  • Show the decision. The answer carries a decision block: the rule it applied, the chosen and runner-up items, and disambiguation_required when two places are too close to call.

02Fetch on a miss, re-check when a slot passes

emem does not ship a dataset. It reads open archives on demand and remembers what it read.

  • Materialise. A recall for a reading this node does not hold fetches it from the upstream of record, signs it and stores it, in the same call. The next agent gets it from memory.
  • Stay current. A stored reading answers "the latest" until one slot of its band has passed. After that a newer observation can exist, so the next recall asks again.
  • Sign the gaps. When every scene is cloud, or the upstream has no value, the answer is a signed absence with a typed reason, citable like any fact.

03Sign it: a name for the bytes, a signature over the answer

A fact is named by its own bytes. Change one byte and the name changes, so a quoted name pins the exact reading.

  • Name. The fact body (cell, band, time slot, value, sources, how it was derived) is encoded as canonical CBOR and hashed with BLAKE3. That digest, base32, is the fact_cid.
  • Sign. Every answer carries a receipt: ed25519 over a domain-separated, length-prefixed preimage naming the request, the time served, the primitive, every cell and every fact_cid. Version 2 also binds the fact's Merkle proof.
  • Verify anywhere. Rebuild the preimage from the receipt's own fields, hash it, check the signature against the published key. No callback to us. The same code runs in /verify and in step 03 above.

A signature proves who signed and that nothing changed since. It does not prove the value is true. How the value was made is its own label, in section 06.

04Log it: nothing is rewritten in the dark

Every write lands in a public, append-only log. A signed tree head commits to all of it.

  • Prove inclusion. /v1/log/inclusion returns the audit path from an entry to the signed head, checkable with log2(n) hashes.
  • Prove it only grew. Pin a head, then ask /v1/log/consistency: a later head must extend the earlier one exactly.
  • Get witnessed. Other operators co-sign our heads, so a split view shown to different readers is detectable.

05Cite it: what each token proves

A token is a short string an agent hands another. The family says what it binds, and how strongly.

tokennamesbindsresolve
emem:fact:<cell>:<cid>one signed readingthe whole body: full 32-byte blake3/v1/memory_token/resolve

emem:raster: · emem:cube:a field, or a field over timearea, band and time, each checked against a signed derivation record/v1/raster/resolve · /v1/cube/resolve
emem:rasterset:several fields as onea signed manifest of member tokens/v1/raster_bundle/resolve
emem:state:one step of an answerthe cids of its inputs and the step before it/v1/state/<cid>
emem:trace:a device's outputa verified, chained execution trace; never the pixels/v1/trace_resolve
emem:entity:one real-world objectan identity, 16-byte anchor: a shared reference, not shared bytes/v1/entity/resolve
emem:cell:a placenothing: an address, until a fact hangs on it/v1/recall

A descriptor token says what it is without a round-trip: coordinates, date and band are words every model has seen. A resolver refuses one whose place, band or date disagrees with the signed body, so a real cid cannot be passed off under a false claim.

06Say how it was made

Every band carries a class. An agent that only wants numbers it can recompute itself filters for the first two.

direct_sensorthe instrument product, no algorithm in the path: Sentinel-2, Sentinel-1, Copernicus DEM, night lightsrecomputable
deterministic_indexa fixed formula over raw pixels or time: NDVI and the other indices, slope, phenologyrecomputable
model_outputa trained model or published product: land cover, air quality, population, forest change, surface watertrust the signed checkpoint
human_curatedgeometry a person drew: Overture, protected areas, ecoregions, admin boundariestrust the attester
unclassifiednot tagged yet; lowest trust, never claims to be reproducibletrust the attester

Live, from /v1/bands: 43 bands, 13 recomputable (6 sensor, 7 index), 23 model output, 5 human curated, 2 unclassified. deterministic: true on a recall keeps only the recomputable classes, before the receipt is signed.

07Remember a file as its parts

A file becomes one signed index over the units it is made of. An agent reads the index, then only the part it needs.

  • Read. In your tab: markdown by heading, code by definition, JSON by key, CSV by row block, PDFs by page, Word and slides by heading and slide, safetensors and GGUF by tensor, zips by entry, video by box. Anything else by 4 MiB chunk.
  • Ask first. Nothing leaves until you publish, and the page says what would: the text of each part, or only hashes when the bytes stay with you.
  • Sign. A key made in your browser signs each note into its own namespace. The signature covers the path: blake3("emem.memory_write.v2|" + verb + "|" + path + "|" + body_hash + "|" + base).
  • Prove. The page checks, in the tab: the index hashes to its name; any agent recovers it by name alone; emem.dev countersigned the write; the log includes it; one part folds to the signed root.

08Answer with the facts attached

Ask in words. Every number in the answer is the newest reading of its band, named by the fact that holds it.

  • Route. /v1/ask resolves the place, picks the bands a question needs, recalls or fetches them, and writes the answer from the signed readings.
  • Cite each number. The summary lists every stated value with its fact_cid and age, and one receipt signs all of them. The prose itself is not signed; the facts are.
  • Address the steps. Each stage of the reasoning gets an emem:state: address that commits to its inputs, so an agent can cite, skip or reuse a step.

09Connect, disagree, supersede

  • Bundle. Group many facts under one emem:bundle: an agent cites as a unit.
  • Disagree in the open. When sources conflict, the contradiction is scored and kept with every conflicting fact_cid. Nothing wins silently.
  • Supersede, never erase. A newer attestation supersedes on the transaction-time axis. The old bytes stay replayable with as_of_signed_at.

10Reach it from anywhere

  • MCP. /mcp lists the 18 tools of the core loop; every one of the 114 stays callable by name, and /mcp/full lists them all.
  • A2A. /a2a/tasks runs the same tools as agent-to-agent tasks, from any origin.
  • REST. Every route is in /openapi.json. No keys for reads.
  • Federate. This node witnesses its peers' logs, and independent nodes witness ours.

Retired here: the Clay, Prithvi, Galileo and JEPA-v2 models, and new Tessera embeddings. Facts they signed still resolve and verify.
