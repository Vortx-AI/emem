02From a place name to a signed number

Two POSTs. The recall comes back with the value, its unit, the upstream source, and a 64-byte ed25519 receipt over the canonical preimage.

SHstep 1 · locate
$ curl -sX POST https://emem.dev/v1/locate \
    -H 'content-type: application/json' \
    -d '{"q":"South Mumbai"}' | jq .cell64
"defi.zb4d7.ze56c.zf24c"
SHstep 2 · recall
$ curl -sX POST https://emem.dev/v1/recall \
    -H 'content-type: application/json' \

03What it is, and how it works

An LLM asked what is at a place will usually guess. emem is the missing handle: a stable address for every patch of Earth, and a signed fact at that address any agent can read and verify.

A language model has no shared memory of the physical world. The cell64 grid gives every ~9.55 m patch a token-like address that is the same on every responder. Read a cell and you get a fact — elevation, weather, land cover, a foundation embedding — that is ed25519-signed and content-addressed by its fact_cid. Quote that CID in a chat and a colleague pulls byte-identical bytes from any replica and checks the signature in their browser at /verify, with no callback to the issuer.

Facts link to each other through typed edges (disagrees_with, supersedes, relates_to) and improve over time: when two attesters disagree, emem scores the contradiction and keeps both CIDs rather than silently picking one, and an opt-in refinement loop flags facts for re-attestation. A later attestation supersedes an earlier one on the transaction-time axis without erasing the old bytes.

04What agents do with it

Six things an agent reaches for. Each is one call; each answer carries a receipt.

recall Recall any place-time POST /v1/recall Cell × bands → signed facts. Auto-fetches on a miss, then signs the result. Warm reads land in ~10 ms.
verify Verify offline /verify Recompute the BLAKE3 preimage and check the ed25519 receipt against the responder pubkey — no callback to us.
remember Give the agent memory /v1/state · /v1/memory_token · /v1/memory_bundle State vectors, memory tokens, bundles, BGE-768 search over the agent’s own files, bi-temporal recall. Memory docs →
hunt Discover hotspots POST /v1/hunt For questions that don’t anchor on one place. Sweeps a region for a pattern across 12 events and ranks the top cells.
forecast Forecast & solve jepa_predict · heat_solve · wave_solve jepa_predict is a closed-form AR(2) NDVI model; heat_solve and wave_solve integrate physics on the signed grid. Each pins its input fact_cids.
compose Compose algorithms 159 recipes · /v1/triple_consensus Each recipe carries a formula, input bands, and a citation. triple_consensus scores change with three independent foundation encoders.

05Built with emem

eudr.dev is an independent EU Deforestation Regulation compliance agent. Every paragraph it quotes resolves to an ed25519-signed fact_cid served from this responder.

It ingests a shipment plot, dispatches /v1/eudr_dds against the cell64-tiled forest baseline, and returns a Due Diligence Statement shaped to Annex II of Regulation (EU) 2023/1115. The per-cell algorithm eudr_compliance@1 implements the Article 2(4) forest test — >0.5 ha, >5 m height, >10 % canopy cover — against the JRC GFC2020 V3 baseline. The agent runs independently and is not affiliated with any EU institution. Each finding paste-resolves at /verify; the schema is at /v1/schemas/eudr_dds.json.

06Verifying without trusting

Every answer is signed. The responder pubkey is the only trust anchor.

The preimage is a deterministic concatenation, so any agent recomputes it offline and checks the signature — verify in the browser at /verify or with POST /v1/verify_receipt. A receipt issued today verifies in any year, on any node, as long as the pubkey is preserved, and the same answer is reproducible on any peer that holds the fact. The preimage, in full →

Where this is going

Forward-looking. Everything below the line ships in 0.0.9; the federation routing does not.

emem is built to be a protocol, not a single service. Because every fact is content-addressed and signed, any responder can serve it and any client can verify it offline, without trusting the source. Today that runs as one hosted responder plus self-hosted nodes. The design target is a federation of independent responders that resolve the same content ids byte-for-byte, cross-cite each other’s attestations, and record where they disagree, so the shared memory gets more trustworthy the more agents read and write against it.

None of the multi-host federation routing ships in 0.0.9. What ships today is the substrate that makes it possible: content addressing, signed receipts, typed temporal edges, multi-attester contradiction scoring, and a deterministic refinement loop.
