00An LLM token, but for places on Earth

Agents hallucinate reality because they have no shared memory of the physical world. emem is that memory: every place on Earth gets one stable token, every fact at that token is signed, and any responder serves the same bytes for the same token forever.

A language model tokenises text so its layers can reason over symbols instead of raw characters. emem tokenises Earth for the same reason: agents need a finite alphabet for places before they can reason, remember, or cite. The cell64 grid is that alphabet — a 64-bit identifier per ~9.55 m square at the equator, content-addressed, deterministic, and the same on every responder.

The right-hand column is the unlock. A receipt-bearing fact survives the session, survives the model, survives the responder. Quote the fact_cid in a chat and your colleague can pull byte-identical bytes from any replica and verify the signature in their browser at /verify — no callback to the issuer.

Four things every agent currently lacks. emem provides each at the protocol layer.

persistent world state Each conversation starts from zero; the model forgets what was at this cell last week. cell × band × tslot → fact is durable. An agent quotes fact_cid across sessions; the next agent resolves the same bytes.
shared environmental memory Two agents arguing about a place have no common reference and both guess. emem hands them one cell64 they both anchor on, plus signed receipts they both verify offline.
deterministic grounding LLM outputs about places drift between calls. A receipt over blake3-canonical CBOR reproduces byte-for-byte; ed25519 verification needs no server round-trip.
spatial continuity "near Mount Fuji" means something different to every model. The cell64 grid is ~10 m square at the equator, with antimeridian and pole canonicalisation pinned in code; two queries 1 m apart land in the same cell, deterministically.

The grounding layer changes what an agent can be. Once places have stable tokens and facts at those tokens are signed, the loop is locate → recall → reason → cite — each step content-addressed, each fact verifiable from the receipt alone. agents.md walks the loop; §03 shows the first call.

04bReal agents already run on this

eudr.dev is an independent EU Deforestation Regulation compliance agent. Every paragraph it quotes resolves to an ed25519-signed fact_cid served from this responder.

The agent ingests a shipment plot, dispatches /v1/eudr_dds against the cell64-tiled forest baseline, and returns a Due Diligence Statement shaped to Annex II of Regulation (EU) 2023/1115. The per-cell algorithm eudr_compliance@1 implements Article 2(4) as written — >0.5 ha, >5 m height, >10 % canopy cover, excluding land predominantly under agricultural or urban use. Forest baseline is JRC GFC2020 V3 (the Commission’s expected non-binding baseline, live single-COG materialiser at JEODPP), corroborated against Hansen GFC v1.12 treecover2000. Article 2(28) dispatch picks POINT (≤4 ha non-cattle) vs POLYGON (>4 ha or any cattle plot under HS 0102/0201/0202).

Driver attribution (Sims et al. 2025) and RADD Sentinel-1 disturbance alerts layer on as refinement; both currently materialise typed Absence because the upstreams do not honour HTTP Range and the responder will not fabricate a value for a connector it cannot read. The Article 9(1)(b) legality disclaimer ships in the same envelope — land tenure, FPIC, country-of-origin laws are structurally out of EO scope and need a partner module before TRACES NT submission. Honest by construction.

The agent is operated independently and is not affiliated with, endorsed by, or sponsored by any EU institution. The cite-back surface is the same one you can drive from your own MCP client: every finding paste-resolves at /verify, and the schema at /v1/schemas/eudr_dds.json cites the exact EUR-Lex paragraph each field maps to.

04cCarbon-credit verifier

An agent that cross-checks carbon offset claims against signed satellite evidence: forest cover baselines, deforestation trajectories, soil organic carbon, and vegetation condition.

Ingest a project polygon and a claimed baseline year. The agent calls /v1/forest for Hansen tree cover 2000 baseline + year-of-loss, /v1/soil for SoilGrids organic carbon at 0–30 cm, and /v1/ndvi for Sentinel-2 NDVI. Each fact is ed25519-signed and content-addressed — the receipt’s fact_cid is citable in VM0042 monitoring reports.

The deforestation_alert_ndvi_drop@1 algorithm detects NDVI drops exceeding the alert threshold between consecutive tslots; hansen.loss_year confirms loss timing against the Global Forest Change baseline. Together they answer whether a claimed “avoided deforestation” credit is backed by an actual standing-forest baseline. Soil carbon (soilgrids.soc_0_30cm) adds below-ground verification for projects claiming soil sequestration. Every number traces back to a signed receipt.

04dInsurance flood pre-screen

A property-risk agent that pre-screens addresses for flood exposure using signed elevation, 37-year surface-water history, precipitation nowcast, and SAR-derived water extent — before an underwriter opens the file.

The agent takes an address or lat/lng, calls /v1/elevation for Copernicus DEM 30 m (land) plus GMRT (bathymetry), /v1/water for JRC Global Surface Water recurrence (1984–2021) plus Sentinel-1 backscatter, and /v1/weather for MET Norway precipitation nowcast. Every input band is a signed fact — the insurer cites fact_cid values in the policy file and any auditor re-verifies offline via /v1/verify_receipt. Precipitation updates every six hours; surface-water recurrence is a 37-year JRC baseline; Sentinel-1 SAR cuts through cloud cover for real-time flood-extent detection. The agent surfaces what the data says and what it does not — caveats[] notes grid resolution and revisit cadence.

05The memory substrate

Below the recall surface sits a typed, signed, searchable memory substrate. State is the read motion (planet-keyed dense vector). The memory token is the cite motion (one string any pipeline can paste). Memory files give an agent a writable scratchpad whose every edit is ed25519-signed and content-addressed. Every read carries the same bi-temporal axis pair: as_of_tslot for what the world looked like on a given date; as_of_signed_at for what the system knew on a given date.

read · 128-D /v1/state {cell, encoder?, view?} Dense signed state at any place. view=encoder returns one foundation embedding (default geotessera, 128-D); view=cube returns the full 1792-D cube. Cell may be a place name; the geocoder cascade resolves it. Cold cells materialise on miss, then sign.
cite · 1 string /v1/memory_token memt:<cell64>:<fact_cid> Compose a single colon-separated handle the agent can paste in chat, write to a long-term store, or quote across processes. Resolves back to the exact bytes on any responder that holds the fact.
dereference /v1/memory_token/resolve {token} Single round-trip dereference: parse the token, fetch the fact by CID, return the canonical body plus the offline-verify URL. Returns 404 with a typed reason if the responder doesn’t hold the fact.

Two more verbs fan the state read. /v1/state_multi fans across every wired foundation encoder (geotessera, clay_v1, prithvi_eo2, galileo) for the same cell, returning a per-encoder map plus a typed missing[] list when an encoder is not wired at this responder. /v1/state_diff takes one cell and two tslots and returns the delta vector, its L2 norm, and the cosine between the two source vectors, with both source fact_cids so the agent can quote both attestations as evidence.

Above the read surface sits a writable memory substrate the agent owns. /v1/memory_bundle takes N (cell, band, tslot) triples and returns one signed envelope — the memb:<bundle_cid> token is the multi-fact analogue of memt:. The six file-op verbs (memory_view · memory_create · memory_str_replace · memory_insert · memory_delete · memory_rename) conform to Anthropic’s memory tool spec (header context-management-2025-06-27): the “files” are signed, content-addressed blobs under a path tree rooted at /memories/. Each file carries a kind from the CoALA / LangMem taxonomy — episodic for observations of events, semantic for durable learned facts, procedural for playbooks, resource for scratchpads — and memory_list_by_kind returns only the slice the agent asked for.

Writes can be capability-bound. Paths under /memories/by_attester/<pubkey_short>/… are write-restricted to the holder of the corresponding ed25519 private key: every memory_create in that namespace carries an attester: {pubkey_b32, sig_b32} block where the signature is computed over blake3("emem.memory_write|" + verb + "|" + path + "|" + body_hash). Wrong key → 401 memory_attestation_invalid. Wrong namespace → 403. Bare /memories/… stays anyone-writable and back-compat with the unsigned form.

Three primitives turn the substrate from storage into a queryable knowledge surface. /v1/memory/search embeds the query through BGE-base-en-v1.5 and runs cosine against a LanceDB IVF_PQ partition (memory_text_index_d768.lance) over every memory file’s contents — the agent paraphrases, the index finds. /v1/memory_contradictions walks the parallel multi-attester index and scores disagreement per band kind: scalar bands by normalised spread against the documented physical range, vector bands by 1 minus mean cosine, categorical bands by 1 minus mode-share. /v1/memory/sse opens an event stream filtered by path_prefix · kind · attester so a compliance subscriber or a downstream agent receives every write the moment its sled commit lands.

The substrate is intentionally typed at every boundary. Vector-only bands accept /v1/state; scalar bands return a typed 422 pointing the agent at /v1/recall. Empty cells return a typed 404 pointing at /v1/materializers. Bi-temporal queries with an inverted bound return 400 invalid_temporal_bound; a malformed timestamp returns 400 invalid_signed_at_format. Receipts carry an as_of block when the bound is non-empty; pre-bi-temporal receipts deserialise byte-identically because the field is absent. Memory file writes are append-only at the content-address layer — memory_delete drops the path index but the blob lives on, addressable through memory_file_history. No silent zero-fills, no last-writer-wins, no opaque mutation.

05bWhat the substrate is for

Five production problems we built the substrate to solve. Each call sketch is paste-runnable against emem.dev; every receipt verifies offline at /verify.

Audit-grade point-in-time evidence

An auditor in 2027 asks whether a plot was forest on 2020-12-31 according to your system at the time of the DDS submission, not according to today’s reprocessed tiles. Last-writer-wins memory loses the original; Zep’s bi-temporal graph keeps both timestamps but issues unsigned facts that an admin can rewrite. emem pairs as_of_tslot + as_of_signed_at on every read with content-addressed signed receipts: the auditor takes a 2026-05 receipt to any peer node and verifies the BLAKE3 preimage and ed25519 signature without trusting our server.

POST /v1/recall { cell, band: "jrc_tmf_v3", as_of_tslot: 1609372800, as_of_signed_at: "2026-05-15T00:00:00Z" }
POST /v1/verify_receipt { receipt }   # any peer, any time, no network back to us

Insurance underwriting — what did we know when we bound the policy

A claim filed today disputes wildfire perimeter on a 2024-09 policy bind date. Mem0 and LangMem give “current memory” with timestamped extracts but no valid-time / transaction-time split. Anthropic’s memory tool stores plain files an operator can edit. The substrate’s bi-temporal axis + ed25519 capability binding pins the bind-time evidence under the underwriter’s pubkey namespace; nobody including us can retroactively edit the path.

POST /v1/recall_polygon { geometry, band: "modis.lst_day_8day", as_of_signed_at: "2024-09-10T00:00:00Z" }
POST /v1/memory_bundle  { triples, purpose: "policy POL-1234 bind evidence" }   # returns memb:<cid>

Multi-attester supply-chain provenance

Four sourcing agents (forester, mill, customs, brand) each push location and biomass claims about the same plot; one is wrong. Recent multi-agent failure research finds ~37 % of cross-agent breakdowns are memory-shaped: last-writer-wins on shared state. Mem0’s scoped writes don’t carry per-agent signatures; Letta’s shared blocks don’t either. The substrate routes each writer through /memories/by_attester/<pubkey>/… and the multi-attester index keeps both CIDs at the same canonical key; /v1/memory_contradictions scores the disagreement and quotes both fact_cids so the brand agent can act on signed evidence.

POST /v1/memory_contradictions { cell_prefix: "defi.zb5f9", band: "indices.ndvi", min_severity: 0.2 }
# returns: [{ cell, band, tslot, attestations: [...signed disagreements...], severity, kind }]

Hallucination prevention via signed reads

The MINJA memory-injection attack (NeurIPS 2025) hit 95 % success on agent memory stores through query-only interaction — agents implicitly trust their own memory. Mem0, LangMem, and Anthropic’s memory tool persist unsigned strings; a poisoned memory looks identical to a real one. Every memory_view and /v1/recall return the signer pubkey; the agent’s “did I really learn this” check becomes signature verification against a trusted set, not a trust assumption.

# every read carries: { value, signer_pubkey_b32, signed_at, fact_cid }
# agent rule: if signer_pubkey_b32 ∉ trusted_set: ignore + alert

Real-time compliance subscription — EU AI Act Article 12

Article 12 (high-risk systems, applicable 2026-08) requires automatic event logging across the lifecycle, with logs generated by the system and verifiable to third parties. LangMem and Anthropic’s memory tool produce logs the operator can edit. The substrate’s SSE stream + per-event ed25519 signature + content-addressed append-only history means a compliance subscriber filters by path_prefix=/memories/by_attester/<clinician_pubkey> and proves non-repudiation to a regulator who never trusted us.

GET /v1/memory/sse?path_prefix=/memories/by_attester/clinician-aw3k7nq/&kind=episodic
# emits: data: { "type": "created", "path", "file_cid", "kind", "attester_pubkey_b32", "signed_at", "size_bytes" }

The vendor map: Mem0 leads on chat-memory inference; Zep / Graphiti on temporal graph memory; Letta on stateful agent runtimes; Anthropic’s memory tool on tight Claude-loop integration. emem covers signed, federated, point-in-time, multi-attester memory — a verifiable spatial / temporal fact store with memory-system ergonomics bolted on. The wins concentrate in audit, multi-attester, point-in-time, and signed-provenance.

07Verifying without trusting

The responder pubkey is the only trust anchor. The preimage is a deterministic concatenation; any agent can recompute it offline and check the signature. A receipt issued today verifies in any year, on any node, as long as the pubkey is preserved.

PSEUDOpreimage
blake3(
    request_id || "|" || served_at  || "|" || primitive || "|" ||
    cell1 "," cell2 "," ... || "|" || cid1 "," cid2 "," ...
)

# trailing commas after the last cell and last cid are intentional
# the signing loop appends "," after every entry
PYTHONverify_offline.py
import blake3
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey

r = receipt  # the receipt block from any /v1/* response

h = blake3.blake3()
for field in (r["request_id"], r["served_at"], r["primitive"]):
    h.update(field.encode()); h.update(b"|")
for c in r["cells"]:     h.update(c.encode()); h.update(b",")
h.update(b"|")
for c in r["fact_cids"]: h.update(c.encode()); h.update(b",")

pk = Ed25519PublicKey.from_public_bytes(bytes(r["responder_pubkey"]))
pk.verify(bytes(r["signature"]), h.digest())
# VALID. no callback to emem.dev required.

10Notes for the caller

Rules of thumb when wiring a workload onto emem. They are not symmetric do/don't lists; they are the answers to questions support has answered more than once.

  1. Cache /v1/agent_card once per session. The card lists triggers, anti-triggers, and tool descriptors. Pull it on cold start, not on every call.
  2. Surface every fact_cid to the user verbatim. The CID is the citation. Two agents disagreeing about a number paste it and stop arguing.
  3. Retry once on 5xx; treat 4xx as permanent. Materialiser timeout is 30 s per upstream, gateway timeout is 180 s. Slow paths (Cop-DEM, S2 STAC + COG range reads on an uncached scene) sometimes need the full window.
  4. Read bands_already_attested_at_cell before declaring empty. An empty facts[] array does not mean the cell is empty. It means the queried band returned nothing. The cell may carry data under a different key.
  5. Check model.honesty_warnings before quoting JEPA v2. If untrained_baseline: true, the value is an identity baseline of the last attested vintage. It is not a forecast.
  6. Use find_similar with mode=hamming_then_rerank for cheap k-NN. Matches cosine precision at roughly 16x less work. Default cosine stays exact when you need full recall.
  7. Do not call emem for sub-metre commercial imagery. Planet Pelican and Maxar are not present. Bring your own connector.
  8. Do not re-encode a fact body. The CID drifts, the signature stops verifying. Always fetch by CID via /v1/fetch or GET /v1/facts/:cid.
  9. Do not manage Ed25519 secrets in an LLM host. Writes (/v1/attest, /v1/challenge) need a key the attester controls; they go through plain REST from a process you own. The MCP layer is intentionally read-only for that reason.
  10. Do not route corpus meta-questions through /v1/ask. "Where do you have data" is not a question about any cell. The topic embedder will guess a region and produce noise. Call /v1/coverage_matrix or /v1/discover directly.

When in doubt, walk the loop. discover, locate, recall, reason, verify. Every step is idempotent and signed.
