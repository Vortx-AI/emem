Examples · Air-gapped nodes

Sign at the edge. Verify anywhere.

Run emem on machines with no network: satellite payloads, robots, field computers and sealed networks. Files arrive in a directory, the node signs a custody record for each one, and only the record leaves. Anyone checks it offline, with no account.

Run the quickstart Read the node's README

Keep the payload. Send the record.

Each record names one payload's bytes, size and time, carries the node's signature, and checks against the payload wherever the payload travels.

Run it where nothing connects.

The node needs an input directory and an output directory. It needs no Rust, no clone of the repository and no network on the machine it runs on.

Sign on a satellite payload.

Two mounts are enough: an uplinked directory in and a downlinked directory out. The node key can come from the environment, so it never touches storage.

Sign on a robot or a field computer.

Static binaries for arm64 boards such as a Jetson, and for amd64. Each write is atomic and fsynced, so a brown-out leaves a whole record, never half of one.

Sign on a host you do not own.

Run it with --network none, --read-only, --cap-drop ALL and a read-only input mount. The node refuses symlinks and bounds every read.

Check inside a sealed network.

Carry emem facts and their receipts in as files, and check them there against emem.dev's published key.

Ship two static binaries.

One crate builds both. They share the record schema, the identity file and the signing code, and run as two images so each keeps its own privileges.

emem-airgap

Sign each file.

Reads the input directory, signs one emem.custody.v1 record per file and writes it to the output directory. It opens no socket and uses no database.

emem-encode, the optional sidecar

Trace the run.

Reads what the kernel shows in /proc and /sys, signs an emem.os_trace.v1 trace and binds the payload digests of its window. The record then cites the trace, as custody_with_trace.

Run the quickstart in one command.

On a machine with Docker, the script goes from nothing to a signed and verified record in six steps, and prints each command before it runs it.

Try itsh
curl -fsSL -o quickstart.sh \
  https://raw.githubusercontent.com/Vortx-AI/emem/main/crates/emem-airgap/quickstart.sh
less quickstart.sh
sh quickstart.sh ./mynode
Run it sealeddocker
docker run --rm --network none --read-only \
  --cap-drop ALL --security-opt no-new-privileges \
  --user 65532:65532 \
  -v /host/in:/in:ro -v /host/out:/out -v /host/data:/data \
  ghcr.io/vortx-ai/emem-airgap:latest \
    --input /in --output /out --data /data \
    --profile orbital.satellite.v1 \
    --platform nvidia.jetson-orin \
    --observed-at now

Check a record with the binary alone.

verify needs no network and no server. It exits 0 on a valid record and 1 on a bad signature or a different file, so it can gate a script or a CI job.

Verify a record and its payloadsh
emem-airgap verify \
  out/frame_001.tif.<node8>.20261107T090000Z.custody.json \
  in/frame_001.tif

name       frame_001.tif

Carry signed memory into a sealed network.

An emem fact is named by the BLAKE3 hash of its canonical bytes, and every receipt is signed with emem.dev's published key. So a copy carried across the gap checks against its own name, with no call back.

Save the fact and its receipt.

Resolve an emem:fact token outside, then save the fact's bytes from GET /v1/facts/<cid> with Accept: application/cbor.

Check them inside, offline.

verify.py rebuilds the receipt's preimage, checks its Ed25519 signature against the published key and hashes each saved fact. Plain Python 3, no third-party package, no network call.

Run a full node inside.

The ghcr.io/vortx-ai/emem image runs on amd64 and arm64. With EMEM_AUTO_MATERIALIZE=0 it serves the facts it holds and signs with its own key.

Carry a fact insh
# outside: resolve the token and save the fact's bytes
curl -sX POST https://emem.dev/v1/memory_token/resolve -H 'content-type: application/json' \
  -d '{"token":"emem:fact:defi.zb55e.zbc6e.dara:34gz4k3xjv5xzden7hqreo57grk3x7q6vzbyc5ef6lrtk46r463q"}' > fact.json
curl -s -H 'accept: application/cbor' \
  https://emem.dev/v1/facts/34gz4k3xjv5xzden7hqreo57grk3x7q6vzbyc5ef6lrtk46r463q \
  > facts/34gz4k3xjv5xzden7hqreo57grk3x7q6vzbyc5ef6lrtk46r463q.cbor

# inside, with no network (tools/verifiers/emem-verify-receipt)
python3 verify.py fact.json --facts facts
