### Differences from the plan

The code differs from the plan in these places. Each item comes from the
code or from a live call on 7 November 2026.

- Scope reaches recall, recall_polygon, query_region, trajectory,
  find_similar, state, state_multi, memory_bundle and eudr_dds.
  `memory_search` has no `scope` field by design. It searches memory notes,
  and the scope index holds facts only
  (`crates/emem-primitives/src/memory_search/mod.rs`).
- A scoped `find_similar` skips the vector index and scans every candidate.
  The vector index has no scope column.
- The receipt does not put the scope digest at a fixed position. Scope,
  `as_of` and edges enter the preimage as tagged segments, only when
  present (`sign_receipt_v1_inner` in `crates/emem-storage/src/server.rs`).
  Live receipts carry `preimage_version: 2`.
- The Vault key comes from the responder's Ed25519 secret, not from the
  attester's key. HKDF-SHA512 derives a ChaCha20-Poly1305 key. The signature
  that opens an entry must verify under the responder's public key. Thus only the
  operator of a responder can open a Vault entry on it.
- Core entries come first in a `memory_view` listing. There is no
  `include_core` flag.
- The A2A card reports `protocolVersion` `1.0` and `version` `2.4.4`. It
  lists 18 skills, one for each core tool. It has no `dataTypes` field.
- The MCP server does not use the `rmcp` crate. The dependency line in
  `crates/emem-mcp/Cargo.toml` is a comment. The MCP code is in
  `crates/emem-api-rest/src/lib.rs`.
- `example_args` is not a separate field in `tools/list`. It is in each
  tool's description. `GET /v1/tools` returns it as `example_args`. The test
  `every_example_satisfies_its_own_schema` checks each example.
- The sleep-time agent signs no writes. It sends memory writes with no
  `attester` block, so emem.dev refuses them. Its default label
  `sleep_agent_v1` is not in a registry in `crates/emem-core/data/`.
  [sleep-agent.md](../sleep-agent.md) gives the details.
- `emem-scorecard` gets a signed receipt from the responder in `--live`
  mode. Its `--self-test` output has no signature. No `bench.yml` workflow
  exists in `.github/workflows/`, and README has no scorecard section.

### Check the status yourself

These calls ran on emem.dev on 7 November 2026. They are reads and need no
key.

```sh
# A2A card: protocolVersion 1.0, version 2.4.4, 18 skills
curl -s https://emem.dev/.well-known/agent-card.json \
  | jq '{protocolVersion, version, skills: (.skills | length)}'

# MCP: protocolVersion 2025-11-25 and a tasks entry in capabilities
curl -s -X POST https://emem.dev/mcp -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"check","version":"0"}}}' \
  | jq '.result | {protocolVersion, tasks: .capabilities.tasks}'

# Edges: an unknown subject gives an empty list, not an error
curl -s -X POST https://emem.dev/v1/edges/recall -H 'content-type: application/json' \
  -d '{"subj":"emem:entity:none","pred":"knows"}' | jq '{edges, objs}'

# Scope: a scope with no facts gives 0 facts; the receipt carries the scope
curl -s -X POST https://emem.dev/v1/recall -H 'content-type: application/json' \
  -d '{"cell":"defi.zb592.nUkO.zEzE","bands":["indices.ndvi"],"scope":{"user_id":"docs-check-nobody"}}' \
  | jq '{facts: (.facts | length), scope: .receipt.scope, pv: .receipt.preimage_version}'
```

The last call returned `facts: 0`, `scope: {"user_id": "docs-check-nobody"}`
and `pv: 2`.

## The plan as written on 28 May 2026

The rest of this page gives the plan in short form. It keeps the goals and
the designs. The original text is in the git history of this file.

The plan came from an audit by five agents on 28 May 2026. The audit
compared emem with Letta, Mem0, MIRIX, Graphiti and the A2A protocol. The
plan put both releases in one document because v0.0.9 used the data model
that v0.0.8 added.

### Limits set by the plan

- No wire-format break through v0.0.9. The receipt preimage and the cell64
  bit layout stay frozen.
- The responder never writes for an agent without an explicit Ed25519
  signature from that agent. Agents sign their commands. The responder signs receipts.

### v0.0.8: scope, memory kinds, A2A, LangMem

Goal: make emem a memory backend for multi-agent systems, A2A runtimes and
LangGraph. Every change is additive.

#### Change 1: scope tags on every write

A four-part scope `{user_id, agent_id, run_id, org_id}` goes with each
write. Each field is optional. Every read primitive takes a matching
filter. The receipt binds the scope. Mem0, Letta and Graphiti each have a
similar axis. Without it, a sub-agent's note appears in the parent agent's
recall.

Design: a `Scope` struct with canonical CBOR, a BLAKE3 digest of it in the
receipt preimage, a sled tree `emem.scope_index`, and
`Storage::scan_cell_in_scope`. With no scope, the preimage stays the same
as before, so old receipts still verify. Planned tests:
`scope_round_trip`, `legacy_v007_receipts_still_verify` and
`scope_in_preimage`. `scope_round_trip` exists in
`crates/emem-primitives/src/recall.rs`.

#### Change 2: Core and Vault memory kinds

MIRIX names six memory types. emem had four: episodic, semantic,
procedural and resource. The plan added `core` and `vault`. Core holds the
persona that an agent always reads first. Vault holds secrets in a sealed
form. Vault entries stay out of `memory_search` and out of contradiction
scans. Planned tests: `core_pinned_in_view`, `vault_round_trip_with_cap` and
`vault_excluded_from_search`. The two Vault tests exist in
`crates/emem-api-rest/src/lib.rs`.

#### Change 3: A2A agent card

Serve an A2A agent card at `/.well-known/agent.json` and
`/.well-known/agent-card.json`. Map the core MCP tools to A2A skills. Add
`POST /a2a/tasks`, which runs the same handlers as the REST routes and
returns the receipt as the task artifact. The plan cited A2A v1.2 and a
[Linux Foundation press release](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)
about adoption.

#### Change 4: LangMem `BaseStore` adapter

Publish `emem-langmem` to PyPI. It wraps the memory routes as a LangChain
`BaseStore` with `put`, `get`, `search` and `delete`. A namespace and a key
become a memory path.

#### Side lane: `example_args` for every tool

Give every tool a small valid example of its arguments. MCP hosts can show
it to the model. A test checks each example against the tool's own input
schema.

#### v0.0.8 release gate

`cargo test --workspace` and `cargo clippy --workspace -- -D warnings`
pass. `mdbook build docs` passes. Each change has a round-trip test.
`emem-langmem` installs and round-trips. The agent card validates against
the A2A JSON Schema. `CHANGELOG.md` has a 0.0.8 entry.

### v0.0.9: edges, sleep-time agent, MCP 2025-11-25, scorecard

Goal: add typed relations between entities, an LLM loop that combines notes,
the MCP 2025-11-25 task model, and benchmark numbers.

#### Change 5: temporal knowledge-graph edges

An edge is `(subj, pred, obj, valid_from, valid_to)`. A newer edge
supersedes an older one without a delete. `valid_to` empty means the edge
is still in force. `as_of` uses the same two-time rule as band facts. Edges
use the same receipt. Routes: `POST /v1/edges` to write and
`POST /v1/edges/recall` to read. MCP tool: `emem_edges_recall`. Recall
takes `include: ["edges"]`. Planned tests: `edge_supersession` and
`edge_in_receipt`. The storage test `edge_supersession_as_of` exists in
`crates/emem-storage/src/lib.rs`.

#### Change 6: Sleep-time agent loop

An opt-in background worker. When the responder is idle, it picks the
notes with the most churn, asks an LLM to merge near-duplicates, and writes
the result. The old notes stay. The new note supersedes them through the
two-time rule. The plan named Letta's
[sleep-time agents](https://docs.letta.com/guides/agents/architectures/sleeptime/)
as the model. Settings: `EMEM_SLEEP_AGENT_INTERVAL_SECS` and
`EMEM_SLEEP_AGENT_BUDGET_USD`. Both exist in the code.

#### Change 7: MCP 2025-11-25 upgrade

Move the MCP protocol version from `2024-11-05` to `2025-11-25`. A long
tool call returns a task handle at once, and the client polls `tasks/get`.
The plan also asked for server-initiated sampling and elicitation. The project did
not build those two parts. Planned tests: `async_task_handle` and
`sampling_round_trip`. Only `async_task_handle` exists.

#### Change 8: `emem-scorecard` and a published score

A binary that runs MemoryAgentBench
([arXiv 2507.05257](https://arxiv.org/html/2507.05257v1)) and LongMemEval
style tests against a local responder. It reports four axes and a
LongMemEval-S topline. The plan also asked for a weekly workflow and a
score table in README. The project did not build those two parts.

#### v0.0.9 release gate

The v0.0.8 gate, plus two items. `emem-scorecard` gives scores on all four
axes against a fresh responder. The MCP server passes a conformance test
for the `2025-11-25` shape.

### Planned order

1. v0.0.8: A2A, then LangMem, then Core and Vault, then scope.
2. Tag v0.0.8.
3. v0.0.9: MCP 2025-11-25, then edges, then the sleep-time agent, then the
   scorecard.
4. Tag v0.0.9.

Edges needed the scope axis from v0.0.8, and the sleep-time agent needed
edges. Thus v0.0.9 could not start before v0.0.8 shipped.

### Left out of the plan on purpose

- Graph queries past "subject and predicate to objects at a time". No
  Datalog and no shortest path. The plan set these for v0.1.0.
- Video and audio encoders.
- Reads across more than one responder. The plan set these for v0.2.0.
- Migration of v0.0.6 receipts to the new preimage rule. Old receipts
  still verify.
