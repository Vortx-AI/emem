# emem Gemma-4 "explain" sidecar (spike)

An **optional, clearly-unsigned** natural-language layer over emem's signed
facts. It rewords what emem already signed; it never produces a fact.

## The hard rule it respects

emem's `/v1/ask` answer is **deterministic and LLM-free on purpose** — the
`answer` string is a pure projection of the signed fact set, so the receipt is
byte-stable and re-verifiable offline. **This sidecar does not touch that path.**
It is a separate process that:

- reads an emem `/v1/ask` response (the signed facts + the deterministic answer),
- asks **Gemma-4-12B** to phrase it for a non-expert,
- returns prose marked **`signed: false`** with an explicit disclaimer.

The model is instructed to interpret only the numbers emem already signed and to
never invent a value. The signed artifact remains the emem receipt
(`fact_cids` + `signature`); this prose is commentary, not ground truth.

Gemma-4 12B is the embedding-first *validation* emem cites on `/how-it-works`
(encoder-free, Google DeepMind, June 2026). Here it is used purely as a reasoner
over already-signed facts — emem still does not slice a language model.

## Run

```bash
# transformers >= 5.x venv that supports gemma4_unified (the box has one):
/home/ubuntu/memory-injection/.venv/bin/python explain_sidecar.py
# loads google/gemma-4-12B-it in 4-bit (~7 GB GPU), serves 127.0.0.1:5071
```

Health / use:

```bash
curl localhost:5071/health
# pipe a real signed answer straight in:
curl -s -X POST https://emem.dev/v1/ask -H 'content-type: application/json' \
  -d '{"q":"what is the air quality here","cell":"defi.zb4d8.zf96c.zf464","include":["band_observations","algorithm_outcomes"]}' \
| jq '{ask: .}' \
| curl -s -X POST localhost:5071/explain -H 'content-type: application/json' -d @-
```

Response shape:

```json
{
  "explanation": "Air quality here is good ... PM2.5 is 22 µg/m³ ...",
  "signed": false,
  "disclaimer": "Generated by Gemma-4-12B from emem's already-signed facts ...",
  "model": "google/gemma-4-12B-it",
  "source_signed_fact_count": 42,
  "latency_ms": 1700
}
```

## Env

| var | default | meaning |
|---|---|---|
| `EMEM_EXPLAIN_BIND` | `127.0.0.1:5071` | listen address |
| `EMEM_EXPLAIN_MODEL` | `google/gemma-4-12B-it` | HF model id (use `google/gemma-4-E2B-it` for a smaller footprint) |
| `EMEM_EXPLAIN_MAX_TOKENS` | `160` | generation cap |

## Optional emem wiring (NOT done — deliberately staged)

A thin `POST /v1/explain` proxy in the Rust server could forward an ask response
here and attach the result as an **`explanation`** block flagged `signed:false`,
alongside (never replacing) the signed `answer`/`receipt`. It is intentionally
not wired yet: the deterministic, signable fact path must stay untouched, and the
sidecar should prove out as a standalone spike first.
