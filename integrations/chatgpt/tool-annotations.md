# Tool annotations and why each is set

Every tool emem serves over MCP sends all four hints as explicit booleans. This file gives the reason for each value, taken from the tool's dispatch arm in `crates/emem-api-rest/src/lib.rs` (`mcp_tool_call_inner`) and the functions it calls. The values themselves live in `crates/emem-mcp/src/lib.rs`, and the test `hints_match_what_the_handlers_do` there pins the ones most likely to be edited by mistake.

## What each hint means here

- **readOnlyHint** is false when the handler can persist anything to the shared store: a call to `sign_and_persist`, `put_attestation`, a `materialize_*` function, `recall_with_auto_materialize`, a memory write, an entity or alias write, or a bundle or derivation record. Reading a cell that holds no fact for the requested band materialises one: the server fetches upstream open data, signs a new fact and appends it to a public log. That counts as a write. Caches internal to this node (the geocoder cache, result caches, the search index) do not. Signing a response receipt without storing it is not a write.
- **destructiveHint** is true only when a call can replace, move or remove what an existing path reads. Facts are append-only, so no fact-producing tool is destructive.
- **idempotentHint** is true when repeating a call with the same arguments adds nothing further to the store. A materialise-on-miss read is idempotent because the second call finds the fact the first one stored. A tool that signs a new record with the current time on every call is not.
- **openWorldHint** is true when a call can reach a service outside this node (a geocoder, an upstream Earth-observation archive, a caller-supplied URL). A tool that reads or writes only this node's own store is closed-world. That includes the memory, derivation and alias writes: they change state other agents can read, which readOnlyHint and destructiveHint already say, but their world is this node's store. The MCP spec gives a memory tool as its closed-world example.

Many read tools take a place name where a cell64 is expected. The MCP pre-flight in `mcp_tool_call_inner`, or the handler's own `resolve_cell_field`, then geocodes it through `locate_inner`, which can call Photon, Nominatim and a Wikidata decision stage. That is why some tools that only read the local store are still open-world.
